# Full Implementation Plan: Private-First Personal Streaming Platform

## 0) Guiding constraints (must-haves)
- Default all uploaded content to `visibility=private` and `rights_status=personal_only`.
- Public playback only when rights-cleared and explicitly enabled by admin.
- Never issue permanent public stream URLs.
- Every playback flow (private/auth/public) uses short-lived signed playback sessions generated by backend.
- Mobile app never receives Cloudflare API tokens.
- Share/playback/refresh tokens are stored hashed in DB.

## 1) Monorepo foundation
1. Finalize directory skeleton and coding standards.
2. Add strict `.editorconfig`, PHP CS fixer config, Dart lint rules.
3. Add CI workflow for backend tests + flutter tests + static analysis.

## 2) Backend core framework
1. Harden request/response/router:
   - route params, method overrides, middleware pipeline, exception-safe handling.
2. Add robust error handler with structured JSON for API and HTML for admin.
3. Add config loader with typed getters and boot validation for required env keys.
4. Add CORS config for API origin allow-list.
5. Add rate limiter abstraction (Redis preferred; in-memory fallback for local).

## 3) Database and migrations
1. Replace initial migration with full schema from spec:
   - users, refresh_tokens, categories, genres, series, seasons, episodes, movies,
     media_assets, content_categories, content_genres, watch_progress,
     user_content_access, share_links, playback_sessions, admin_audit_logs.
2. Add all required indexes and unique constraints.
3. Add rollback-capable migration runner and migration tracking table.
4. Add seeders:
   - admin@example.com / ChangeMe123!
   - one category, one genre, one draft/private sample movie.

## 4) Auth and user management
1. API auth:
   - POST /api/auth/login, /refresh, /logout, GET /api/me.
   - Access token + refresh token rotation with hashed token persistence.
2. Admin auth:
   - session-based login/logout, CSRF-protected forms, secure cookie flags.
3. Authorization:
   - roles `admin` and `viewer`, inactive account lockout.
4. Optional admin 2FA placeholder data model + service hooks.

## 5) Access policy and rights enforcement
1. Implement `AccessPolicyService::canWatch(?User $user, string $playableType, int $playableId, ?string $shareToken = null): bool` against DB data.
2. Enforce content state rules:
   - draft/archived blocked except admin.
   - private => assignment/admin.
   - authenticated => active login.
   - unlisted => valid share token OR active assigned login.
   - public => published + enabled + rights-cleared + public window valid.
3. Enforce admin visibility mutation guards:
   - reject public if rights not cleared.
   - never disable signed playback requirement.
   - write audit log diffs.

## 6) Catalog domain
1. Repositories and services for categories, genres, movies, series, seasons, episodes.
2. Public-safe DTO transformers that never expose `provider_uid` or raw storage keys.
3. API endpoints:
   - /api/home, /api/categories, /api/genres, /api/series, /api/movies, details, seasons/episodes,
   - /api/continue-watching.
4. Public endpoints:
   - /public/catalog, /public/movies/{slug}, /public/series/{slug} (listed public only).

## 7) Playback session flow
1. Build POST /api/playback-sessions and POST /public/playback-sessions.
2. Validate access via `AccessPolicyService` only on backend.
3. Create signed playback session records with hashed token and expiry.
4. Generate short-lived Stream token and HLS manifest URL.
5. Public anonymous session default expiry: 30 minutes.
6. Apply rate limiting on public playback session creation.

## 8) Cloudflare Stream integration
1. Implement direct upload URL creation endpoint for admin use.
2. Implement status sync and deletion operations.
3. Implement signed playback token generation using signing key PEM.
4. Add integration tests for request signing and failure modes.
5. Fail closed if signing/env invalid.

## 9) Cloudflare R2 integration
1. Implement SigV4 presigned upload/read URL generation.
2. Add object deletion operation.
3. Add strict content-type and key namespace validation.
4. Ensure URLs are short-lived and not persisted as public permanent links.

## 10) Watch progress
1. Implement endpoints:
   - POST /api/watch-progress
   - POST /api/watch-progress/mark-watched
   - POST /api/watch-progress/clear
2. Upsert per user/playable unique key.
3. Mark completed at >=90% or explicit completion event.

## 11) Admin portal (server-rendered PHP)
1. Auth pages + dashboard metrics cards.
2. CRUD pages for movies, series, seasons, episodes, categories, genres, users.
3. Media management pages:
   - direct upload URL trigger
   - status sync
   - delete.
4. Access management pages:
   - assignments, visibility controls, share link create/revoke.
5. Audit log index with filters.
6. CSRF tokens in all POST forms.

## 12) Flutter mobile app (Riverpod)
1. Core layers:
   - Dio API client with auth interceptor + refresh retry once on 401.
   - secure token storage.
2. Feature modules:
   - splash, auth, home, catalog, series, movies, player, continue watching, profile.
3. Player flow:
   - request backend playback session.
   - play returned HLS URL.
   - heartbeat progress every 15–30 sec + on pause/seek/background/complete.
4. UI states:
   - loading/error/empty for all major screens.
5. Resume behavior:
   - resume unless completed, otherwise restart by default.

## 13) Testing strategy
1. Backend unit tests:
   - full AccessPolicy matrix from spec.
   - WatchProgress completion/clear/save behavior.
2. Backend feature tests:
   - playback session endpoint for auth/public flows.
3. Flutter tests:
   - model parsing tests.
   - login and catalog loading/empty widget tests.
4. CI gates:
   - composer test
   - flutter analyze
   - flutter test

## 14) Security hardening checklist
- Prepared statements only (PDO).
- Password hashing: `password_hash` + `password_verify`.
- CSRF protection for admin forms.
- Strict input validation with whitelist enums.
- Token hashing for refresh/share/playback sessions.
- Rate limiting for login and public playback.
- Sensitive logs redaction.
- No secrets in repository; `.env.example` placeholders only.

## 15) Delivery sequence (incremental PRs)
1. PR-1: Backend core hardening + full schema + migration/seeders.
2. PR-2: Auth (API + admin), middleware, CSRF, rate limiting hooks.
3. PR-3: Catalog + access policy + public/private endpoint shaping.
4. PR-4: Playback sessions + Stream integration + R2 integration.
5. PR-5: Admin portal CRUD + audit + visibility controls.
6. PR-6: Flutter app foundation + auth/home/catalog.
7. PR-7: Flutter player + progress sync + polish.
8. PR-8: Final test expansion, docs, and production readiness checklist.
